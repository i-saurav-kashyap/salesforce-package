Part 4

Build the Application First

You cannot learn packaging with a Hello World. Packaging problems only appear when you have an object customers store data in, Apex customers cannot edit, a UI that carries your namespace, permissions you must ship, and configuration customers are allowed to change. So we build that first.

Everything on this page already exists on disk, in sample-project/ next to this site. The code blocks below are read directly from those files, so what you see is what you deploy.

The product: “Ops Toolkit”

A field-operations add-on. A customer's dispatcher raises Service Requests against an Account, the system applies an SLA to compute a due date, and a console lets a field lead see what is open and close it out.

It ships as two 2GP packages plus one 1GP package used purely for the legacy exercise:

PackageGenerationContainsDepends on
Ops Toolkit Core2GPService_Request__c + fields, validation rule, list view, Ops_Setting__mdt + a record, custom labels, tab, ServiceRequestService, ServiceRequestSelector, OpsSettings, tests, permission set—
Ops Toolkit Field Ops2GPserviceRequestConsole LWC, ServiceRequestConsoleController, Lightning app, flow, permission setOps Toolkit Core
Ops Toolkit Core (1GP)1GPThe same core metadata, deployed into a 1GP packaging org—

What each directory is, precisely

  • packages/<name>/ — a package directory. In 2GP, the boundary of a package is literally “the files under this path”. Move a file between these folders and you have moved it between packages. That is why the folder layout is an architectural decision, not cosmetics.
  • main/default/ — convention inherited from the DX default project. Nothing magic; it keeps room for other bundles (main/test/) later.
  • config/*.json — scratch org definition files. Not packaged. They describe the org you want the Dev Hub to build.
  • scripts/ — not packaged. Your local automation. Everything here should also be runnable by CI.
  • sfdx-project.json — the most important file in a 2GP repo. Package names, versions, dependencies, namespace, and the auto-maintained packageAliases map from friendly names to 0Ho/04t IDs. Always commit it after creating a version.

Business logic — and your first irreversible API decision

sample-project/packages/core/main/default/classes/ServiceRequestService.cls
/**
 * Business logic for service requests. This is the class other packages call,
 * so its global surface is an API contract that must live forever.
 */
global with sharing class ServiceRequestService {

    global class ServiceRequestException extends Exception {}

    /** Simple DTO so callers (LWC, other packages) never depend on our SObject shape. */
    global class RequestInput {
        global String summary;
        global String priority;
        global Id accountId;
        global Date dueDate;
    }

    global static Id createRequest(RequestInput input) {
        if (input == null || String.isBlank(input.summary)) {
            throw new ServiceRequestException(Label.Ops_Summary_Required);
        }
        Service_Request__c sr = new Service_Request__c(
            Summary__c      = input.summary.trim(),
            Priority__c     = String.isBlank(input.priority) ? OpsSettings.defaultPriority() : input.priority,
            Status__c       = 'New',
            Account__c      = input.accountId,
            Requested_On__c = Date.today(),
            Due_Date__c     = input.dueDate != null ? input.dueDate : Date.today().addDays(OpsSettings.slaDays())
        );
        // USER_MODE makes the platform enforce CRUD + FLS on the DML for us.
        Database.SaveResult result = Database.insert(sr, true, AccessLevel.USER_MODE);
        return result.getId();
    }

    global static void complete(Set<Id> requestIds) {
        if (requestIds == null || requestIds.isEmpty()) {
            return;
        }
        List<Service_Request__c> toUpdate = new List<Service_Request__c>();
        for (Id requestId : requestIds) {
            toUpdate.add(new Service_Request__c(Id = requestId, Status__c = 'Completed'));
        }
        Database.update(toUpdate, true, AccessLevel.USER_MODE);
    }

    /** Convenience for other packages: is the running user able to use this app at all? */
    global static Boolean currentUserCanUse() {
        return Schema.SObjectType.Service_Request__c.isAccessible()
            && Schema.SObjectType.Service_Request__c.isCreateable();
    }
}

Read the global keywords again. In a managed package:

  • public = visible only inside your namespace. You can change it freely forever.
  • global = visible to subscribers and other packages. Once released you can never change its signature, never remove it, and never make it less visible. You can only add.

Beginners mark everything global “to be safe”. That is the opposite of safe: it freezes your internals forever. Mark global only what is genuinely an API.

All SOQL in one place

sample-project/packages/core/main/default/classes/ServiceRequestSelector.cls
/**
 * All SOQL for Service_Request__c lives here.
 *
 * Security notes that matter for the AppExchange Security Review:
 *  - `with sharing` so record-level sharing of the SUBSCRIBER org is respected.
 *  - `WITH USER_MODE` makes the platform enforce object and field level security
 *    on the query itself, so a user without FLS on Due_Date__c gets an error
 *    rather than silently reading data they should not see.
 *  - Bind variables (:accountId) instead of string concatenation: no SOQL injection.
 */
public with sharing class ServiceRequestSelector {

    private static final Set<String> SORTABLE = new Set<String>{
        'Name', 'Status__c', 'Priority__c', 'Due_Date__c', 'Requested_On__c'
    };

    public List<Service_Request__c> openRequests(Integer maxRows) {
        Integer safeLimit = maxRows == null || maxRows <= 0 || maxRows > 200 ? 50 : maxRows;
        return [
            SELECT Id, Name, Summary__c, Status__c, Priority__c,
                   Due_Date__c, Requested_On__c, Is_Overdue__c,
                   Account__c, Account__r.Name
            FROM Service_Request__c
            WHERE Status__c NOT IN ('Completed', 'Cancelled')
            WITH USER_MODE
            ORDER BY Due_Date__c ASC NULLS LAST
            LIMIT :safeLimit
        ];
    }

    public List<Service_Request__c> byAccount(Id accountId) {
        return [
            SELECT Id, Name, Summary__c, Status__c, Priority__c, Due_Date__c
            FROM Service_Request__c
            WHERE Account__c = :accountId
            WITH USER_MODE
            ORDER BY Requested_On__c DESC
            LIMIT 200
        ];
    }

    /**
     * Dynamic sorting done safely: the ORDER BY column is validated against an
     * allow-list, never taken from user input directly. String.escapeSingleQuotes
     * alone does NOT protect an ORDER BY clause.
     */
    public List<Service_Request__c> openRequestsSorted(String sortField, Boolean ascending) {
        String field = SORTABLE.contains(sortField) ? sortField : 'Due_Date__c';
        String direction = ascending == false ? 'DESC' : 'ASC';
        String soql =
            'SELECT Id, Name, Summary__c, Status__c, Priority__c, Due_Date__c ' +
            'FROM Service_Request__c ' +
            'WHERE Status__c NOT IN (\'Completed\', \'Cancelled\') ' +
            'ORDER BY ' + field + ' ' + direction + ' NULLS LAST LIMIT 200';
        return Database.query(soql, AccessLevel.USER_MODE);
    }
}

Three Security-Review-relevant patterns are in that file: with sharing, WITH USER_MODE / AccessLevel.USER_MODE, and an allow-list for the dynamic ORDER BY. Part 13 makes you break and fix each one.

Tests — the thing that gates your release

sample-project/packages/core/main/default/classes/ServiceRequestServiceTest.cls
@IsTest
private class ServiceRequestServiceTest {

    @IsTest
    static void createsRequestWithSlaDueDate() {
        ServiceRequestService.RequestInput input = new ServiceRequestService.RequestInput();
        input.summary = 'Generator will not start';

        Test.startTest();
        Id newId = ServiceRequestService.createRequest(input);
        Test.stopTest();

        Service_Request__c saved = [
            SELECT Status__c, Priority__c, Due_Date__c, Requested_On__c
            FROM Service_Request__c WHERE Id = :newId
        ];
        Assert.areEqual('New', saved.Status__c, 'New requests start in New');
        Assert.areEqual(OpsSettings.defaultPriority(), saved.Priority__c, 'Falls back to configured default priority');
        Assert.areEqual(Date.today().addDays(OpsSettings.slaDays()), saved.Due_Date__c, 'Due date is derived from the SLA setting');
    }

    @IsTest
    static void rejectsBlankSummary() {
        ServiceRequestService.RequestInput input = new ServiceRequestService.RequestInput();
        input.summary = '   ';
        try {
            ServiceRequestService.createRequest(input);
            Assert.fail('Expected a ServiceRequestException');
        } catch (ServiceRequestService.ServiceRequestException e) {
            Assert.areEqual(Label.Ops_Summary_Required, e.getMessage(), 'User-facing message comes from a custom label');
        }
    }

    @IsTest
    static void completeMarksRequestsCompleted() {
        Service_Request__c sr = new Service_Request__c(
            Summary__c = 'Replace filter', Status__c = 'New', Requested_On__c = Date.today()
        );
        insert sr;

        Test.startTest();
        ServiceRequestService.complete(new Set<Id>{ sr.Id });
        Test.stopTest();

        Assert.areEqual('Completed', [SELECT Status__c FROM Service_Request__c WHERE Id = :sr.Id].Status__c);
    }

    @IsTest
    static void selectorReturnsOnlyOpenRequests() {
        insert new List<Service_Request__c>{
            new Service_Request__c(Summary__c = 'Open one',  Status__c = 'New',       Requested_On__c = Date.today()),
            new Service_Request__c(Summary__c = 'Closed one', Status__c = 'Completed', Requested_On__c = Date.today())
        };

        List<Service_Request__c> open = new ServiceRequestSelector().openRequests(10);

        Assert.areEqual(1, open.size(), 'Completed requests must be excluded');
        Assert.areEqual('Open one', open[0].Summary__c);
    }

    @IsTest
    static void sortFieldIsAllowListed() {
        insert new Service_Request__c(Summary__c = 'Sortable', Status__c = 'New', Requested_On__c = Date.today());
        // A hostile sort field must be ignored rather than injected into the query.
        List<Service_Request__c> rows =
            new ServiceRequestSelector().openRequestsSorted('Name FROM Account WHERE Id != null--', true);
        Assert.areEqual(1, rows.size(), 'Query still runs against Service_Request__c only');
    }

    @IsTest
    static void settingsFallBackWhenNoRecord() {
        OpsSettings.overrideForTest = new Ops_Setting__mdt(SLA_Days__c = null, Default_Priority__c = null);
        Assert.areEqual(5, OpsSettings.slaDays());
        Assert.areEqual('Medium', OpsSettings.defaultPriority());
    }
}

The dependent package's controller

sample-project/packages/field-ops/main/default/classes/ServiceRequestConsoleController.cls
/**
 * Controller for the serviceRequestConsole LWC.
 *
 * This class lives in the FIELD OPS package and calls global classes that live in
 * the CORE package. That single fact is what makes Field Ops depend on Core:
 * Salesforce resolves `ServiceRequestService` at compile time when the Field Ops
 * package version is built, and the version create fails if Core is not installed
 * into the build environment - which only happens because we declared the
 * dependency in sfdx-project.json.
 */
public with sharing class ServiceRequestConsoleController {

    @AuraEnabled(cacheable=true)
    public static List<Service_Request__c> getOpenRequests(Integer maxRows) {
        try {
            if (!ServiceRequestService.currentUserCanUse()) {
                throw new AuraHandledException(Label.Ops_No_Access);
            }
            return new ServiceRequestSelector().openRequests(maxRows);
        } catch (Exception e) {
            // Never leak a raw stack trace to the UI of a subscriber org.
            throw new AuraHandledException(e.getMessage());
        }
    }

    @AuraEnabled
    public static Id createRequest(String summary, String priority, Id accountId, Date dueDate) {
        try {
            ServiceRequestService.RequestInput input = new ServiceRequestService.RequestInput();
            input.summary   = summary;
            input.priority  = priority;
            input.accountId = accountId;
            input.dueDate   = dueDate;
            return ServiceRequestService.createRequest(input);
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }

    @AuraEnabled
    public static void completeRequests(List<Id> requestIds) {
        try {
            ServiceRequestService.complete(new Set<Id>(requestIds));
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}

The LWC

sample-project/packages/field-ops/main/default/lwc/serviceRequestConsole/serviceRequestConsole.js
import { LightningElement, api, wire, track } from 'lwc';
import { refreshApex } from '@salesforce/apex';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

import getOpenRequests from '@salesforce/apex/ServiceRequestConsoleController.getOpenRequests';
import completeRequests from '@salesforce/apex/ServiceRequestConsoleController.completeRequests';

// Custom labels are namespaced automatically when the package is installed.
import CREATED from '@salesforce/label/c.Ops_Request_Created';

const COLUMNS = [
    { label: 'Number', fieldName: 'Name', initialWidth: 120 },
    { label: 'Summary', fieldName: 'Summary__c' },
    { label: 'Status', fieldName: 'Status__c', initialWidth: 130 },
    { label: 'Priority', fieldName: 'Priority__c', initialWidth: 110 },
    { label: 'Due', fieldName: 'Due_Date__c', type: 'date-local', initialWidth: 120 }
];

export default class ServiceRequestConsole extends LightningElement {
    @api maxRows = 50;

    columns = COLUMNS;
    @track rows = [];
    errorMessage;
    isLoading = true;
    selectedIds = [];
    wiredResult;

    labels = { created: CREATED };

    @wire(getOpenRequests, { maxRows: '$maxRows' })
    handleWire(result) {
        this.wiredResult = result;
        const { data, error } = result;
        if (data) {
            this.rows = data;
            this.errorMessage = undefined;
        } else if (error) {
            this.rows = [];
            this.errorMessage = error?.body?.message ?? 'Unexpected error';
        }
        this.isLoading = false;
    }

    get hasRows() {
        return !this.isLoading && this.rows.length > 0;
    }

    get isEmpty() {
        return !this.isLoading && !this.errorMessage && this.rows.length === 0;
    }

    get nothingSelected() {
        return this.selectedIds.length === 0;
    }

    handleSelection(event) {
        this.selectedIds = event.detail.selectedRows.map((row) => row.Id);
    }

    async handleComplete() {
        this.isLoading = true;
        try {
            await completeRequests({ requestIds: this.selectedIds });
            this.selectedIds = [];
            await refreshApex(this.wiredResult);
            this.toast('Success', 'Requests completed.', 'success');
        } catch (e) {
            this.toast('Could not complete', e?.body?.message ?? 'Unexpected error', 'error');
        } finally {
            this.isLoading = false;
        }
    }

    handleOpenModal() {
        this.dispatchEvent(new CustomEvent('newrequest'));
    }

    toast(title, message, variant) {
        this.dispatchEvent(new ShowToastEvent({ title, message, variant }));
    }
}

What the namespace does to this component. In your dev org you use <c-service-request-console>. In a subscriber org, after install, the same component is <opskit-service-request-console>, the label import c.Ops_Request_Created resolves to opskit__Ops_Request_Created, and the Apex import resolves to opskit.ServiceRequestConsoleController. You write c.; the platform rewrites it. This is exactly why you must test in a non-namespaced org with the package installed.

Rule of thumb: for every component you add to a package, ask “which permission set grants access to this?” Object, fields, Apex classes, tabs, apps, and record types all need explicit grants. If your answer is “the admin will do it”, your install experience is broken.
